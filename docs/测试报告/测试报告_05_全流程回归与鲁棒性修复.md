# 测试报告 05 —— 全流程回归测试与鲁棒性修复

- 测试对象：`HIS_System_Project`（C99 控制台医院信息系统）
- 测试日期：2026-09-20
- 测试方式：`stdin` 脚本化驱动菜单（全流程）+ 边界用例 + 数据文件断言
- 一键复现：`bash HIS_System_Project/tests/full_flow_test.sh`
- 结论：**81 条断言全部通过**；发现并修复 15 项缺陷（其中 5 项为数据损坏/流程安全级）

> 测试脚本会在 `tests/.work/` 下复制一份源码与独立 `data/` 目录运行，**不会改动仓库中的种子数据**；
> 每个用例执行后都会在 `tests/.work/out/<用例>.snapshot/` 留存当时的数据文件快照，便于失败定位。

## 一、测试范围

| 阶段 | 覆盖内容 |

### 1.2 边界与异常

| 类别 | 覆盖用例 |
|---|---|
| 输入校验 | 菜单非数字/超范围/空输入；非法性别；非数字/超范围年龄；非法手机号；身份证校验位不符 |
| 金额边界 | 充值 0（取消）、负数、单次超上限（10 万）、充值后余额超上限、余额不足挂号 |
| 库存边界 | 入库数量非数字 / 超上限；出库与发药超库存；库存总量溢出保护 |

| 输入流 | stdin 关闭（EOF / 管道读完）必须正常退出，不得死循环 |

## 二、发现并修复的缺陷

| # | 级别 | 缺陷 | 证据 / 影响 | 修复 |
|---|---|---|---|---|
| 1 | 严重 | `parseDrugLine` / `parseDoctorLine` / `parseBedLine` / `parseDeptLine` 使用 `sscanf("%[^|]")` 解析，**该转换符无法匹配空字段**，遇到空字段即提前结束，其后所有字段全部丢失 | 种子数据 `drug.txt` 的商品名/别名为空：仅"启动 → 退出"一次，库存即由 `99` 变为 `0`（`M260517001\|…\|0.00\|99\|0\|` → `\|0.00\|0\|0\|`），科室归属同时丢失 | 四个解析函数统一改为 `next_token()` 逐字段解析（与 patient/record/schedule 一致），并保留载入后数值校正 |
| 2 | 严重 | 输入流结束（管道关闭 / `< /dev/null`）时 `getValidChoice` 无限循环刷屏，进程无法退出 | 空 stdin 运行 3 秒即产生约 20 MB 输出 | `getValidChoice` 检测到 `feof(stdin)` 时提示并 `exit(0)`；药品数量等输入循环同样处理 |
| 3 | 严重 | 预约 ID 使用 `GenerateID` 直接生成，**不做查重** | 同一天内重启后序号回退，可生成与历史预约相同的 ID；`FindNode` 只返回首条，取消/退款作用到错误记录 | 预约改用 `generateUniqueID`，生成失败则不扣款直接返回 |
| 4 | 严重 | 门诊发药先扣库存、扣余额，最后才生成记录 ID | 记录 ID 生成失败时，钱和药已扣但**没有任何处方记录**（对账缺口） | 调整顺序：先生成记录 ID，再执行库存/余额变更与插入 |
| 5 | 严重 | ID 序号为 `static` 变量、每次启动从 1 开始，而 `generateUniqueID` 只重试 10 次 | 同一天已创建 ≥10 条记录后重启，该类实体**再也无法生成新 ID**（直接报"无法生成唯一 ID"） | 生成前用 `syncIDSequence()` 扫描同级链表，把序号推进到"当天已有最大序号 + 1"，ID 格式不变 |
| 6 | 中 | 载入的数据不做合理性校正 | 手工/异常写入的 `insurance_ratio > 1` 会算出负费用，挂号反而**增加余额**；负库存、负余额、非法挂号状态、非法 PIN 同样进入业务逻辑 | 各 `parse*` 增加载入校正：医保比例夹紧到 `[0,1]`、余额/库存/费用非负、状态枚举归位、非法 PIN 清空（PIN 非法会导致患者永久无法登录） |
| 7 | 中 | 费用汇总对"已按医保折后"的记录金额再次乘以医保比例估算报销，属**重复计算** | 挂号 3.00 元（原价 10.00、报销 70%）会被再次"报销"，汇总的"总费用/预计自付"与实际收付不符 | 明确 `MedicalRecord.cost` 为"医保结算后患者应付/已付"口径：发药记录改为存自付额（总费用与报销额写入详情），汇总改为直接累计并单列已取消记录 |
| 8 | 中 | 药品入库无数量上限，`d->stock += quantity` 可溢出为负；价格/库存非法输入被 `atoi/atof` 静默当作 0 | 入库 `2147483647` 之类输入会把库存变成负数，后续发药判断全部失真 | 新增 `readDrugQuantity` / `readNonNegativeFloat` / `readNonNegativeInt` 严格解析，单次 1~1,000,000、库存总量上限 100,000,000 并做溢出判断 |
| 9 | 中 | 修改医生账号时若与其它医生冲突，原实现 `break` 跳出**整个修改菜单**并继续打印"[成功] 医生信息修改成功" | 用户会误以为改动已生效，实际未修改且被踢出菜单 | 改为独立冲突标志，仅放弃本次字段修改，菜单保留 |
| 10 | 低 | 取消预约只拦"已取消"，其余状态（如异常状态）同样退款 | 存在重复/越权退款的口子 | 仅允许取消"已预约"状态的预约 |
| 11 | 低 | 管理员新增医疗记录时，详情含 `\|` 会报错但**记录仍被写入**（详情为空） | 数据校验形同虚设 | `inputRecordInfo` 返回状态，校验失败则放弃新增 |
| 12 | 低 | 排班日期仅校验长度与横杠 | `2026-02-30`、`2026-13-01` 可通过 | 新增 `ValidateDateString()`，校验年月日真实存在（含闰年），新增排班与按日期查询均使用 |
| 13 | 低 | 医疗记录费用可由管理员填写负数 | 费用汇总出现负数，语义错误 | 记录费用统一夹紧为非负 |
| 14 | 低 | `FindNode` / `DeleteNode` 未对 `list` / `id` 判空 | 链表分配失败等异常路径下可能空指针崩溃 | 补空指针保护 |
| 15 | 低 | 删除医生失败时仍执行所属科室 `doctor_count--` | 科室医生数可被减到负数，统计失真 | 仅删除成功后递减，且不小于 0 |

### 真实种子数据往返校验

对仓库现有 `data/` 做"启动 → 退出"（触发全量写回）后对比：

```
OK   doctor.txt / dept.txt / bed.txt / drug.txt / record.txt / schedule.txt / appointment.txt  逐字节一致
DIFF patient.txt —— 仅第 1 行 PIN 字段被清空
```

原因：`P260516001` 行的 PIN 字段实为 `R26051`（历史字段错位产物），长度与字符均不合法，
该患者用任何输入都不可能通过校验（永久锁死）。修复后此类非法 PIN 会被清空为"未设置"，
属于**有意的数据修复**，其余字段逐字节保持不变。

## 四、已知差异与未改动项（供后续决策）

1. **诊断/处方记录不扣费**：医生新增诊断记录只登记费用，不扣患者余额（仅挂号与发药扣费）。
   本次仅把费用汇总的口径文案改准确，未改变收费模型。
2. **已完成的挂号仍可取消并退款**：原实现会对"已有诊断/处方记录"给出警告但允许取消，属既有设计，本次未改。
3. **数据文件编码**：仓库现有数据为 GBK，程序不做任何转码（按字节读写），因此新旧数据混用时终端显示可能异常，但数据本身不会损坏。
4. **并发写入**：单文件采用 write-then-rename 原子写，但无跨进程锁，仍按"单机单实例"假设。
5. **`GenerateID` 直接调用**：仍保留为公开函数，除预约外的调用点均已改用 `generateUniqueID`；新增代码请勿直接使用 `GenerateID`。
